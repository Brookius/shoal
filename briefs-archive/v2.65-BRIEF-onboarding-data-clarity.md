# v2.65 — Onboarding & data-storage clarity

**Goal:** a first-time user understands *where their dives are stored* and never
silently loses them. Three pieces, each independently shippable. No new backend —
reuse existing primitives.

## Context / decisions (settled)
- Folder sync works on Android Chrome (Chromium M132+). A **Google Drive folder =
  transparent cloud backup** via Android SAF — no Drive API/OAuth. (CLAUDE.md updated.)
- We **can't force the picker to open into Drive** — `showDirectoryPicker`'s `startIn`
  only takes a well-known dir or a saved handle, never a cloud provider by name. So:
  guide the user with a hint on first pick; the handle is persisted → it's a one-time act.
- **Reuse `_pendingSync`** (already set on every mutation; cleared on Obsidian push) as
  the unified "not yet on the backend" flag. NEW: folder writes must clear it on success.
  No parallel "unsynced" store. Status "unsynced count" = `dives.filter(d=>d._pendingSync)`.
- New persisted state, total: `divelog-last-sync` (ISO ts) and `divelog-welcome-seen` ('1').
- Labels (per user): "On this device" was misleading (sounds like a folder) → **"In your
  browser"**. Folder option = **"In a folder"** (local *or* a Drive folder for cloud).

## Piece 2 — Sync status line  (app.js + obsidian.js + css)
- `renderSyncStatus()` — computes state and renders a strip. Three states:
  - `none`            → "N dives · in your browser only, not backed up" (pending tone)
  - folder/obs, 0 pending → "N dives · synced to {folder name} · {relative last-sync}" (ok)
  - folder/obs, >0 pending → "N dive(s) not synced · tap to retry" (warn, calls `retrySync`)
- `writeToFolder` success → `dive._pendingSync=false`, persist dives, `divelog-last-sync=now`.
  (Failure leaves `_pendingSync` true — that's the unsynced signal.)
- Render targets: `#sidebar-sync` (desktop). Mobile reuses `#sync-banner-log` /
  `#sync-banner-history` in-flow, **only when `syncMode!=='obsidian'`** (don't clobber the
  Obsidian banners); hide that banner-strip ≥600px via CSS so desktop shows only the sidebar.
- `retrySync()` — re-attempt `writeToFolder` for each `_pendingSync` dive (folder) /
  `pushToObsidian` (obsidian), then re-render.
- Call `renderSyncStatus()` on: boot, after save/edit, after any sync, on `show('history'|'log')`.
- Folder-name display: read the saved folder name; only say "Google Drive" if detectable,
  else the folder name (per user's note about local/Proton folders).
