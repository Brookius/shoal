## 1. The job to be done

Plan dives at a location for a date: **is it neaps or springs, what are the tide
times, will the sea/wind be diveable, and — for repetitive dives — what surface
interval do I need between them.** Today this is several websites + paper dive
tables; this folds it into the app, reusing the site's GPS/site data.

## 2. Hard scope boundaries

- **Recreational, no-stop only.** The surface-interval calculator plans
  *within* no-decompression limits — it never plans a decompression obligation.
  See §6 (safety).
- **Browser-first, desktop-enhanced.** Everything works in the browser PWA
  *except* precise tide times, which are a desktop-only capability (the only
  free UK tide API needs a key + has no CORS — §3). The browser shows
  neaps/springs from moon phase; the desktop adds exact high/low times.
- **No new backend.** Keyless+CORS APIs in the browser (Open-Meteo, NOAA);
  the keyed UK tide API runs through the existing Tauri Rust fetch seam.
- **Planning is separate from the log.** A plan is forward-looking; it doesn't
  touch logged dives (promoting a plan → logged dive is a future nicety).
- **No build step for the web app** (carry-forward). The deco engine is a
  *vendored prebuilt bundle*, like Leaflet — not an added build.

## 3. Data sources (decided)

| Need | Source | Key? | CORS? | Where it runs | Horizon |
|---|---|---|---|---|---|
| Neaps/springs + moon phase | **local calc** (astronomical) | — | — | browser + desktop, offline | any date |
| Tide times/heights (UK) | **ADMIRALTY UK Tidal API** (free Discovery, 10k/mo) | yes | no | **desktop only**, via Tauri Rust `fetch` | ~7 days of events |
| Wind + gusts | **Open-Meteo Forecast** | none | yes | browser + desktop | ~16 days |
| Waves / swell | **Open-Meteo Marine** | none | yes | browser + desktop | ~7 days |
| Sea surface temp | **Open-Meteo Marine** (roadmap SST) | none | yes | browser + desktop | ~7 days |
| Coral bleaching (abroad) | **NOAA Coral Reef Watch** (ERDDAP) | none | likely* | browser + desktop | current |
| Surface interval / NDL | **scuba-physics** (Bühlmann ZHL-16C, MIT) | — | — | vendored, local, offline | n/a |

\*Coral bleaching is **deferred to the roadmap** (it was an illustrative example,
not MVP). When built, confirm ERDDAP CORS or route via a desktop Rust fetch.

**Why these:** moon phase makes the headline "neaps or springs" free, offline,
and valid for any future date. Open-Meteo is keyless + CORS + already roadmapped
for SST. Admiralty is the only free UK tide source but is browser-hostile (key
exposure + no CORS), so it lives behind the desktop Rust seam — native HTTP
bypasses CORS and the key never sits in a public site. Bühlmann ZHL-16C is the
open standard; `scuba-physics` (MIT) already does repetitive dives + surface
intervals, and MIT keeps the App-Store/no-GPL position intact.

**Admiralty key handling (desktop):** the user pastes their own free Discovery
key into Settings (stored in `localStorage`, read by the Rust command). One-time
free registration; keeps each user on their own 10k/month quota and avoids
bundling a shared key into a distributable binary.

**Forecast-horizon honesty:** tides + moon phase are astronomical → predictable
years ahead. Wind/waves only exist ~7–16 days out. For a date beyond the
window, show neaps/springs + (desktop) tide times, and a clear "weather
forecast available closer to the date" note instead of empty/guessed values.

## 4. Data model

```javascript
// Saved plans — localStorage 'divelog-plans' → [DivePlan]. Saving is optional;
// conditions are always recomputed live (cache is just for offline re-open).
DivePlan {
  id: 1234567890,                 // Date.now()
  name: 'Cornwall — Whitsun',     // free text
  location: 'Porthkerris',        // site name (free text or from site search)
  gps_lat: 50.05, gps_lng: -5.08, // drives tide station, Open-Meteo, coral
  date: '2026-05-23',             // target date (YYYY-MM-DD)
  dives: [                        // the repetitive sequence, for the SI calc
    { seq: 1, depth: 30, time: 25, gas: 'Air' },
    { seq: 2, depth: 18, time: 40, gas: 'Nitrox 32' },
  ],
  notes: '',
  _conditions: { /* Conditions, cached on save */ },
}

// Computed for {gps_lat, gps_lng, date}. Null fields = unavailable (out of
// forecast horizon, offline, or browser build for tideEvents).
Conditions {
  moon:      { phase: 0.62, name: 'Waxing gibbous', illumination: 0.82 },
  tideClass: 'spring' | 'neap' | 'mid',     // derived from moon phase, any date
  tideEvents: [ { type: 'high'|'low', timeISO, heightM } ] | null,  // Admiralty (desktop)
  tideRange:  4.2 | null,                   // m; confirms spring/neap (desktop)
  wind:    { speedKn, gustKn, dirDeg, at } | null,        // Open-Meteo
  marine:  { waveM, swellM, swellPeriodS, at } | null,    // Open-Meteo Marine
  sst:     { c } | null,
  coral:   { baa: 0..4, label } | null,                  // NOAA CRW
  windVerdict: 'ok' | 'marginal' | 'too-strong',         // threshold on gust
  horizonNote: string | null,
  fetchedAt: 1234567890,
}

// Surface-interval result (scuba-physics). Recreational/no-stop framing.
SurfacePlan {
  gf: [40, 85],                                 // gradient factors (conservative)
  perDive:   [ { seq, ndlMin, withinNdl: true } ],
  intervals: [ { afterSeq: 1, minSurfaceIntervalMin: 47, note } ],
  disclaimer: 'Planning estimate — your dive computer is the authority.',
}
```

Settings (the cog) additions:
- `divelog-admiralty-key` — desktop only; paste your free Discovery key once.
  Hidden in the browser/mobile build (tides are desktop-only there).
- `divelog-wind-threshold-kn` — the gust cutoff for the "too windy" verdict;
  the main thing the user tunes (default ~25 kn).
- `divelog-conservatism` — preset, **not** a free GF field: `standard` (GF 40/85)
  or `extra` (tighter). There is deliberately **no** "less conservative" option —
  the surface-interval calculator can only be made more cautious, not less.

## 5. Architecture / seams

- **"Plan" becomes a primary nav tab; "Data" is demoted to a Settings cog.**
  Primary tabs (5): **Log · Plan · History · Species · Stats** — Plan next to Log
  as the two "active dive" actions. The old Data panel (sync backends,
  import/export) is reframed as **Settings** behind a cog (top-right of the
  mobile header; sidebar footer on desktop) and absorbs the new planning
  settings (Admiralty key, wind threshold, GF). No hamburger — one secondary
  destination doesn't need a menu. `#panel-plan` reuses the existing site-search
  (`pickSiteSuggestion`, Nominatim + Dive Vibe) for location → GPS + region.
- **Capability seam for tides:** `fetchTideEvents(lat, lng, date)` →
  `isShell()` ? `invoke('fetch_tide_events', …)` (Rust → Admiralty) : `null`
  (browser shows the moon-phase class only). Mirrors `resolveVideoUrl` /
  `transcodeProxies`.
- **Rust command `fetch_tide_events`** — looks up the nearest Admiralty station
  for the coords (stations endpoint), fetches tidal events with the user's key,
  returns normalised `{type, timeISO, heightM}`. Native HTTP → no CORS; key from
  Settings, never in the webview origin.
- **`js/planner.js`** — panel render + the Open-Meteo / NOAA fetches + moon-phase
  math + the SurfacePlan wrapper around the vendored deco lib.
- **`vendor/scuba-physics/`** — prebuilt single-file bundle (UMD/IIFE attaching a
  global, e.g. `window.ScubaPhysics`), vendored like `vendor/leaflet/`. Produced
  once from the MIT npm/TS source; checksum-recorded (supply-chain hygiene).
- **CSP** (`_headers` + `tauri.conf.json`): `connect-src` += `api.open-meteo.com`
  `marine-api.open-meteo.com` and the chosen NOAA ERDDAP host. (Admiralty needs
  no CSP entry — Rust native fetch isn't governed by the webview CSP.)
- **SW:** add `js/planner.js` + the vendored bundle to the SHELL list; bump cache.

## 6. Safety (the one feature where a bug can hurt someone)

- **No-stop recreational only** — the calculator refuses to plan a deco
  obligation; if a planned profile would incur one, it says "exceeds no-stop
  limits — shorten/shallow the dive," not a deco schedule.
- **Conservative gradient factors** (default 40/85), surfaced and adjustable.
- **Prominent, persistent disclaimer** on the panel and in any saved/exported
  plan: *"Planning estimate only. Your dive computer is the authority. Not a
  substitute for proper training, tables, or a computer."*
- Validate the vendored engine against published NDLs (e.g. air NDL ≈ 56 min @
  18 m, ≈ 20 min @ 30 m within model tolerance) in a small test harness before
  shipping.

## 8. Decision log (locked)

- **Bühlmann ZHL-16C, not PADI RDP** — open + documented; RDP tables are
  proprietary. `scuba-physics` (MIT) is the vendored engine.
- **Desktop-only precise tides** — Admiralty free Discovery via the Rust seam;
  browser gets moon-phase neaps/springs. (No keyless+CORS UK tide API exists.)
- **Open-Meteo for wind/sea** — keyless, CORS, ~16/7-day horizon.
- **Coral from NOAA CRW source, not Esri** — same data, no ArcGIS token.
- **Recreational no-stop scope + disclaimer** — non-negotiable.
