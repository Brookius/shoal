## 1. The join model (how sidecars attach to dives)

Bulky per-dive data lives **outside** the dive `.md`, in a
`<dive-basename>.<kind>.json` **sidecar** beside it — `.footage.json` today,
`.profile.json` once profiles ship. The join is the dive's immutable `uid`.

Precise caveat worth stating: the *logical* join is `uid` (stored inside the
sidecar), but file **discovery** derives the sidecar's name from the dive's `.md`
filename (`_filename`). So the `.md` and its sidecars must always share a basename.
In-app edits never change `_filename`, so they can't break it — but a **manual file
rename in the vault** (renaming the `.md` and not the sidecar) silently orphans the
sidecar, because discovery then looks for a name that no longer exists.

## 2. The problem — filename drift

The `.md` filename is frozen at creation (`_filename` is sticky in `saveEdit`), so
renumbering a dive updates only the frontmatter `divenum:` — the filename keeps the
*old* number. That drift is the real hazard: a user browsing the vault sees
`dive-051-…md` containing dive #50, "fixes" it by hand in Finder/Obsidian, and
silently orphans the sidecar with no idea why. **Kill the drift and you kill the
temptation.**

## 3. Decision — coordinated canonical renaming

- On save, derive the canonical filename from the *current* `divenum` + `site`. If
  it differs from `_filename`, rename — moving the `.md` **and every sidecar**
  (`.footage.json`, `.profile.json`) together, then update `_filename`. This also
  heals already-drifted files (like the one in the vault now) the next time their
  dive is saved.
- "Rename" is **write-new-then-delete-old** on every backend — Obsidian REST and
  folder sync have no atomic rename (Android content-URIs especially; see the
  `writeToFolder` retry note in app.js). Write the full new set, update `_filename`
  only once it is on disk, then delete the old set. A crash mid-way leaves
  duplicates (deduped by `uid` on load), never an orphan.
- **Collision-safe:** if the canonical name is already held by a *different* `uid`
  (two dives at one site sharing a number after a mistake), append a short `uid`
  suffix rather than overwrite. More robust than today, where two same-name dives
  already clobber each other at creation.
- Fires only when the canonical name actually differs from `_filename` — heals drift
  on a drifted dive's next save, no churn on clean edits.

## 4. Optional — one-time repair pass

Coordinated renaming only heals a drifted file the next time *that* dive is saved —
files never re-edited stay mislabelled. To fix all drift in one go, add a one-shot
"normalize filenames" repair: walk every dive, compare `_filename` to its canonical
name, rename the mismatches (moving sidecars with them, via the same
write-new-then-delete-old path). Mirror the existing `migrateLegacyFootage`
read-repair pattern (obsidian.js) — run once on load behind a guard flag, or expose
it as a button in Settings & data. Idempotent: a second run finds nothing to do.

## 5. Optional — deeper guardrail (belt-and-suspenders)

The above removes the *temptation* to manual-rename; it doesn't make a manual rename
*harmless*. To make the join survive any filename meddling, change sidecar
**discovery** from "derive the expected name from the `.md`" to "scan the folder's
`*.footage.json` / `*.profile.json`, read each one's internal `diveUid`, join by
`uid`." Then a renamed `.md` or sidecar still finds its partner as long as both
files exist. Costs a content read per sidecar instead of a name match and touches
the existing footage loader (`loadAllSidecars`, video.js) — a separate decision,
noted here because it is the only thing that fully closes the "corruption with no
idea why" gap.

## 6. Files touched

| File | Change |
|---|---|
| `js/app.js` / `js/obsidian.js` | derive canonical name on save; write-new-then-delete-old for `.md` + all sidecars; `uid`-suffix on collision |
| `js/markdown.js` | sidecar filename derivation stays the join convention |
| `js/obsidian.js` | (optional §4) one-time "normalize filenames" repair, mirroring `migrateLegacyFootage` |
| `js/video.js` | (optional §5) `loadAllSidecars` discovers by scanning + internal `diveUid` instead of derived filename |
| `sw.js` | bump cache version on any shell-file change |

## 7. Why separate, and when

General hygiene — benefits the **footage** sidecar and heals the drift Luke already
has, with zero dependency on profile import. Build it independently; the profile
sidecar (`BRIEF-dive-profile-import.md`) then inherits the safety for free by joining
the set being moved.
