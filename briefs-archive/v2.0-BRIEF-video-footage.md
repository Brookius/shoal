# v2.0 Brief — Video Footage Feature

**Self-contained implementation brief for a fresh session (Sonnet).** Read this
once end-to-end before touching code. The two mockups it references *are* the
visual specification — open them in a browser:

- `mockups/mockup-video-linking.html` — expanded dive card with the new ▶
  glyphs on sighting rows and the **Footage section**.
- `mockups/mockup-footage-modal.html` — the dedicated **Footage modal**
  (data-entry workspace) at realistic density, including the bulk-import
  affordance and the unlinked-sightings list.

Also read first: `DECISIONS.md → "Modular migration"`, `CLAUDE colour UI.md`
(the colour system), and the README → `index.html` code map.

---

## 1. The job to be done

The user reviews GoPro footage *days/weeks after diving* to log species
sightings he wasn't able to record on the boat. Two real pains:

1. *"Which videos have I already reviewed?"* — GoPro filenames are opaque
   (`GX011280.MP4`); no current way to track review state.
2. *"Where did I see the leaf frogfish?"* — current method is a free-text
   note with a filename + timestamp. Hard to search, hard to act on.

v2.0 ships the **metadata foundation** for this: linking videos and
per-sighting timestamps to dives, plus a dedicated workspace for entering
that data. **In-app playback is explicitly NOT in v2.0** (deferred to v2.1+).
**Species Profile / search view is NOT in v2.0** (deferred to a later
release). The honest scope of v2.0 is *"plumbing + dive-centric workspace +
visible indicators."*

## 2. Hard scope boundaries (do not exceed)

**In scope (v2.0):**
- Per-dive `videos: []` list + per-sighting optional `video`/`time` fields.
- New **Footage** section on the expanded dive card (display).
- Subtle ▶ glyph on sighting rows that have a video reference.
- New **Footage modal** — dedicated workspace for video work on a *logged*
  dive. Bulk file import via picker + drag-and-drop. Add sightings from
  timestamps. Attach existing sightings to videos. Toggle reviewed state.
- Frontmatter sync (parser/generator/roundtrip) so videos persist in the
  Obsidian vault.
- Service-worker lockstep for any new files added to `SHELL`.

**Out of scope — do not implement (deferred):**
- ❌ Video *playback* (`<video>` element, blob URLs, `currentTime` jumping)
- ❌ File System Access API (`showOpenFilePicker`, persistent folder handles,
   IndexedDB-stored handles)
- ❌ Cloud upload or hosting (R2, YouTube, Vimeo, etc.)
- ❌ Species Profile / "where did I see X?" search lookup
- ❌ Cross-dive bulk import (whole-trip folder, auto-distribute by date)
- ❌ MP4 container parsing (duration, GPS, exact recording timestamp from
   metadata boxes)
- ❌ Smart date-matching suggestions ("these files were recorded on the same
   day as dive #X, attach?")
- ❌ Friendly aliases / human labels for filenames (user explicitly declined)
- ❌ Adding footage from the **new-dive form** (user explicitly declined —
   the Footage modal is **only** accessible from a *logged* dive)

If you find yourself reaching for any of the above, **stop and confirm with
the user first.**

## 3. Architectural constraints (carry-forward from the migration)

These are non-negotiable. Read `DECISIONS.md → "Modular migration"`.

- **Classic ordered `<script src>` files. NO ES modules.** Functions stay
  global. New JS goes in `js/footage.js` loaded before the main inline
  `<script>`. Inline `onclick=` handlers must keep resolving.
- **No build tools.** Vanilla browser-native APIs only.
- **Single-purpose, bisectable commits** (one per phase below). Each
  independently smoke-testable. No automated tests — discipline *is* the net.
- **Service worker lockstep**: every file added → `SHELL` += that path,
  `CACHE` bumped (`divelog-vN` → `v(N+1)`), or offline silently breaks.
- **Frontmatter compatibility**: existing `.md` files with no `videos:` key
  must continue loading (treat as `[]`).
- **Colour system v2** (`CLAUDE colour UI.md`): reuse only.
  - ▶ glyph: `var(--accent)` (interactive role)
  - "✓ reviewed": `var(--success)` (scale-positive role)
  - "● unreviewed": `var(--pending)` (needs-attention role)
  - **No new reserved colours.**
- **Section pattern** (matches expanded card): small-caps mono accent label
  + hairline rule + content. The mockups already follow it.
- **No File System Access API in v2.0.** Use `<input type="file" multiple
  accept="video/*">` + HTML5 drag-and-drop. **The browser must not read
  video file bytes** — only `File.name`, `File.lastModified`, `File.size`.

## 4. Data model changes

### In-memory dive object

Extend with:
```js
{
  ...existing fields...,
  videos: [                                            // NEW — array, may be empty
    {
      file: 'GX011280.MP4',                            // string — the filename
      modified: 1747143751000,                         // number — ms since epoch
      size: 4145923584,                                // number — bytes
      reviewed: true                                   // boolean — user toggle
    },
    ...
  ],
  marine: [
    {
      ...existing sighting fields (commonName, scientificName,
       aphiaId, group, abundance, validated)...,
      video: 'GX021280.MP4',                           // NEW (optional) — filename, must match a `videos[].file`
      time: '04:23'                                    // NEW (optional) — mm:ss within that video
    },
    ...
  ]
}
```

`video` and `time` are both optional and travel as a pair. A sighting with
`video` set but no `time` is permitted (interpreted as "somewhere in this
video"). A sighting with `time` but no `video` is invalid — never write it.

### Frontmatter YAML representation

Roundtrip in `generateFrontmatter()` ↔ `parseFrontmatter()` ↔
`frontmatterToDive()`:

```yaml
videos:
  - file: "GX011280.MP4"
    modified: "2026-05-13T14:22:31Z"
    size: 4145923584
    reviewed: true
  - file: "GX031280.MP4"
    modified: "2026-05-13T14:53:08Z"
    size: 2103458176
    reviewed: false

species:
  - common: "Leaf frogfish"
    scientific: "Antennarius pictus"
    abundance: "R"
    validated: true
    video: "GX021280.MP4"        # only present if linked
    time: "04:23"                 # only present if linked
```

Notes:
- `modified` is serialised as ISO-8601 in YAML (human-readable in Obsidian)
  but stored as ms-since-epoch in memory.
- Existing dives without a `videos:` block load with `dive.videos = []`.
- Existing sightings without `video`/`time` keys load unchanged.
- Do NOT add `videos:` to frontmatter when the array is empty — keep `.md`
  files clean.

## 5. UI surfaces (visual spec → see mockups)

### A. Expanded dive card (`renderDiveDetail()` and species row builders)

Reference: `mockups/mockup-video-linking.html`

- New `.dd2-footage` section: rendered **only when `d.videos.length > 0`**,
  positioned between **Marine life** and **Notes**.
  - Header: `FOOTAGE  ·  N files · M sightings linked · K unreviewed` (counts derived).
  - Per-video card showing filename, reviewed/unreviewed state chip, list of
    linked sightings sorted by timestamp.
  - "Manage footage" button → opens the Footage modal for this dive.
- Empty state (no videos): a single discreet **"+ Add footage"** button in
  the card body (no section header, no chrome) → opens the modal.
- **New ▶ glyph** in `spRowHtml()` and `spSlideHtml()` — appears next to the
  abundance pill **only when `m.video` is set**. Style: small Cerulean
  glyph, `title` attribute showing the file + timestamp. **Passive in v2.0**
  (no click handler) — purely an at-a-glance indicator.

### B. Footage modal (NEW, dedicated workspace)

Reference: `mockups/mockup-footage-modal.html`

- Modal frame: same overlay/animation pattern as existing `#edit-modal`.
- **Accessible only for already-logged dives.** Entry: the "Manage footage"
  / "+ Add footage" button in the expanded dive card. **Do NOT add any
  entry point from the new-dive form.**
- Header: `FOOTAGE  ·  Dive #N  ·  Site  ·  Region  ·  Day Date`, with ✕
  close.
- Body sections:
  1. **Videos** — list of video cards. Each card:
     - Filename + reviewed/unreviewed chip (chip is clickable, toggles).
     - Linked sightings (sorted by timestamp ascending), each showing
       `MM:SS — common name + abundance pill`.
     - **"+ sighting from this video"** button → expands an **inline form**
       (NOT a sub-modal) with: Timestamp input (`mm:ss`), Species picker
       (reuses the existing species search + browse engine), Abundance
       chooser (R/O/C), Cancel + Save buttons.
  2. **Bulk-import affordance** (below the videos list):
     - Primary: **"Choose videos…"** button → triggers `<input type="file"
       multiple accept="video/*">`.
     - **Drag-and-drop zone** on the modal body — same target, accepts files
       via `dataTransfer.files`.
     - Subtext: *"Filenames and recording dates are read locally. Files
       never leave your device."* (Keep this — it's both reassuring and
       honest.)
  3. **Logged sightings without video** — list of this dive's sightings
     that have no `video` link. Each row has an **"Attach…"** button that
     opens an inline picker: video dropdown (the dive's own videos) +
     timestamp. Save → updates the sighting's `video`/`time`; row moves out
     of "unlinked" and appears nested under the chosen video.
- Footer: **Done** button (just closes).

## 6. Implementation phases (one commit per phase)

Each phase = a single-purpose, bisectable commit. Smoke-test before the next.
Follow the established recipe: `git status` clean baseline → implement →
`jsc` syntax check + manual smoke → docs (CHANGELOG `[Unreleased]`,
DECISIONS progress, README if affected) → user says *"ready to commit"* →
stamp `[Unreleased]` → `## [2.0a] – <date> — …` etc.

### Phase 1 — Data model + frontmatter sync
- Add `videos: []` to new dive objects in `saveDive()` and `saveEdit()`.
- Extend `generateFrontmatter()` to emit `videos:` block when non-empty;
  per-sighting `video`/`time` when present.
- Extend `parseFrontmatter()` and `frontmatterToDive()` to read both back.
- Smoke: create a fresh dive (no videos) → save → reload → unchanged.
  Manually edit a `.md` file's YAML to add a `videos:` block + a sighting
  with `video`/`time` → sync → in-memory dive object now has the new fields.
- **Commit:** `2.0a - Data model: videos + per-sighting video refs`

### Phase 2 — Expanded dive card display
- New CSS for `.dd2-footage` section, video cards, reviewed/unreviewed
  chips, the ▶ glyph (see mockup for visual spec).
- Update `renderDiveDetail()` to render the Footage section when
  `videos.length > 0` (positioned between Marine life and Notes).
- Update `spRowHtml()` and `spSlideHtml()` to emit the ▶ glyph when
  `m.video` is set (passive — no click handler in v2.0).
- "+ Add footage" empty-state button stub (renders, but click does nothing
  yet — Phase 3 wires the modal).
- Smoke: open any dive (no videos) → unchanged. Manually inject a `videos`
  array + a sighting with `video`/`time` via DevTools → reopen → Footage
  section and ▶ render correctly.
- **Commit:** `2.0b - Dive card: Footage section + sighting indicators`

### Phase 3 — Footage modal: open, render, reviewed toggle
- Add modal HTML to `index.html` (analog of `#edit-modal`).
- New file `js/footage.js` (classic script, loaded before main inline
  script): `openFootage(diveId)`, `closeFootage()`, internal render
  functions for the videos list, the reviewed-toggle handler.
- Wire the "Manage footage" / "+ Add footage" button in the expanded dive
  card to `openFootage(d.id)`.
- Reviewed toggle: clicking the chip flips `d.videos[i].reviewed` and
  persists (`localStorage`, then `pushToObsidian` if available — same
  pattern as edit-modal saves).
- `sw.js`: `SHELL` += `/js/footage.js`, `CACHE` bump.
- Smoke: open dive with videos → click Manage footage → modal opens with
  correct data → toggle reviewed → close → reopen → state persists.
- **Commit:** `2.0c - Footage modal: open, render, reviewed toggle`

### Phase 4 — Footage modal: add sighting from timestamp
- Inline "+ sighting from this video" form per video card. Expand/collapse
  in place (no sub-modal).
- Species picker: reuse the existing search + browse engine (the same one
  used in the form and edit modal — be careful with the shared
  `_browseCtx` global; see the documented modal-browse caveat in
  `DECISIONS.md` if it's still open).
- On Save: if a sighting with the same `scientificName` already exists on
  the dive's `marine[]`, attach `video`/`time` to it (don't duplicate).
  Otherwise, push a new sighting onto `marine[]` with the picked species,
  abundance, `video`, `time`, `validated: true`.
- Smoke: open Footage modal → "+ sighting from this video" → pick a species
  → save → close → reopen dive → sighting shows ▶, appears under the
  correct video in Footage section.
- **Commit:** `2.0d - Footage modal: add sighting from timestamp`

### Phase 5 — Attach existing sightings to videos
- Render the "Logged sightings without video" list (sightings on the dive
  with no `video` key).
- Each row's "Attach…" button reveals an inline picker (video dropdown +
  timestamp input).
- On Save: update the sighting's `video`/`time` fields; row moves out of
  the unlinked list and appears nested under the chosen video.
- Smoke: dive with 4 unlinked sightings → attach 2 → close → reopen → 2
  remain unlinked, 2 now show under their videos with ▶ in the species list.
- **Commit:** `2.0e - Footage modal: attach existing sightings`

### Phase 6 — Bulk file import (picker + drag-and-drop)
- Wire "Choose videos…" → triggers a hidden `<input type="file" multiple
  accept="video/*">`. Read each `File`: `name`, `lastModified`, `size`.
  Build `{ file, modified, size, reviewed: false }` per file.
- **Drag-and-drop**: add a drop zone on the modal body. Listen for
  `dragover` (preventDefault → allow drop), `drop` (preventDefault →
  iterate `e.dataTransfer.files`). Same code path as the picker.
- **Dedupe by filename**: if a file's `name` already exists in
  `dive.videos`, skip it silently (don't double-add).
- **Sort**: after import, sort `dive.videos` by `modified` ascending so the
  list reads chronologically (matches recording order).
- **Never read file bytes.** `File.name`/`lastModified`/`size` only. No
  `File.text()`, no `FileReader`, no blob URLs.
- Smoke: pick 3 files in one go → all appear, sorted by modified date →
  pick again with 1 duplicate + 2 new → only the new 2 added → reload →
  list persists.
- **Commit:** `2.0f - Footage modal: bulk import (picker + drag-and-drop)`

### Phase 7 — Final polish + version stamp
- Empty states everywhere (no videos in modal, no unlinked sightings, dive
  with zero marine + zero videos).
- Mobile: modal full-screen-ish at `≤600px` per the existing `#edit-modal`
  responsive pattern.
- Inline-handler sanity: confirm no existing `onclick=` handler broke.
- End-to-end manual smoke test covering all phases.
- Append the v2.0 feature record to `DECISIONS.md` (new section: *Video
  footage feature*).
- Stamp version → 2.0 (per `DECISIONS.md → "Modular migration" →
  Versioning`, v2.0 implies the JS migration is also complete — confirm
  with user before stamping).
- **Commit:** `2.0 - Video footage feature`

## 7. Edge cases & details Sonnet must get right

- **Filenames as keys**: a sighting's `video` field must always reference a
  filename that exists in `dive.videos[].file`. If a user deletes a video
  from the dive's list, *gracefully orphan* any sightings that referenced
  it — clear their `video`/`time` fields and surface them as "unlinked"
  (don't silently lose the sighting itself).
- **Timestamp format**: store as a string `"mm:ss"` (or `"h:mm:ss"` for
  long files). Validate input on Save (accept `4:23`, `04:23`, `1:04:23`).
  Reject other formats.
- **Reviewed toggle independence**: reviewed/unreviewed is a **manual**
  user state, never auto-derived from "has sightings linked." A video can
  be reviewed-and-empty ("watched it, saw nothing notable") and that's
  meaningful.
- **Privacy framing**: the *"Files never leave your device"* line is
  literally true (no byte-read, no upload, no persistent file handle in
  v2.0). Keep this UI copy.
- **Drag-and-drop only inside the modal**: don't add a global page-level
  drop zone — too easy to accidentally drop files anywhere.
- **`dataTransfer.files` filter**: ignore items that aren't video MIME
  types (`type.startsWith('video/')`). Surface a small "skipped N
  non-video files" hint if any were filtered.

## 8. The recipe (mirror the migration discipline)

For each phase:

1. **Clean baseline** — `git status` confirms `index.html` (and any other
   touched files) committed before starting.
2. **Implement** the phase's narrow scope.
3. **Verify**:
   - `jsc js/footage.js` (if touched) — no `SyntaxError`.
   - Extract + parse the inline `<script>`:
     `python3 -c "import re;h=open('index.html').read();open('/tmp/dc.js','w').write(chr(10).join(re.findall(r'<script>(.*?)</script>',h,re.S)))"`
     then `/System/Library/Frameworks/JavaScriptCore.framework/Versions/A/Helpers/jsc /tmp/dc.js 2>&1 | grep -i syntaxerror`
   - Targeted greps (no stale refs, expected refs present).
4. **`sw.js` lockstep** when adding new files: `SHELL` += path, `CACHE`
   `v(N)` → `v(N+1)`.
5. **Docs**:
   - `CHANGELOG.md` `## [Unreleased]` bullet (write *as part of the
     phase*, not retroactively).
   - `DECISIONS.md` progress line under a new "Video footage" decision
     section.
   - `README.md` repo-map row if a new file was added.
6. **Hand off to user for smoke test** with a checklist tailored to that
   phase.
7. **On explicit "ready to commit"**: stamp `[Unreleased]` →
   `## [2.0x] – <date> — <phase summary>` + open a fresh empty
   `[Unreleased]`. Tell the user the exact files to stage in GitHub
   Desktop and which to leave (single-purpose commit).
