# v2.3 Brief — Video sidecar, stable identity, desktop proxy-based tag/watch player

**Self-contained implementation brief.** Read end-to-end before touching code.
Aligned to the live **v2.2** codebase (commit `31dc40c`). Mirrors the working
discipline of the shipped briefs in `briefs-archive/` (`v2.0-BRIEF-video-footage.md`,
`v2.2-BRIEF-history-divefile-redesign.md`).
Builds towards **v2.4**; phases are stamped `2.31 … 2.38` then `2.4`.

**The UI is locked** in `mockups/mockup-video-modal.html` (open it in a browser —
it IS the visual spec for §8). Three desktop surfaces: Tag (default), Tag-mode
with the species picker active, and Watch (animal-first).

Also read first: `DECISIONS.md → "Video footage feature (v2.0)"`, `CLAUDE.md →
Data model`, `js/markdown.js` (the parser this brief deliberately *stops*
touching), `js/footage.js` (the modal being rebuilt), `js/app.js →

## 1. The job to be done

The end goal: **review dive footage inside the app, tag wildlife with timestamps
as you review, and have those tags flow back into the dive record — so reopening a
dive lets you play each clip and jump straight to the moment a species appears.**

Four problems block that today, and this brief clears them in order:

1. **The parser is overloaded.** Video data (`clips[]`) is nested inside the
   dive's species list, parsed by a hand-rolled nested-YAML reader in
   `markdown.js`. Every video iteration risks corrupting irreplaceable biological
   records. → **Move video data to a JSON sidecar.**
2. **Identity is unstable.** `dive.id` is filename-derived for synced dives
   (changes on rename); free-text species are keyed by mutable display name.
   References between files can't survive edits. → **Mint stable ids.**
3. **No playback, no host-agnostic source model.** → **A `sources[]` model +
   `resolveVideoUrl` seam + local player.**
4. **The footage modal is a static two-column list** with no player. → **Rebuild
   it as a full-screen, player-centric Tag ⇄ Watch modal** (the locked mockup).

**v2.3 is desktop-only and proxy-based.** Tagging needs the footage on the review
machine — so the whole video experience is desktop-only; mobile gets nothing
video-related until the cloud phase ships. But the review machine is a *laptop*,
and a dive trip is ~300 GB of 4K masters that live on a NAS / external drive and
can't sit on the laptop (Jellyfin chokes on the masters anyway). So the thing you
review and tag from is a **proxy** — a small re-encode (~10–15 GB/trip) with an
**identical timeline**, so timestamps tagged on the proxy are frame-valid on the
master. The master becomes the archival pointer you record, not the file you open.
Cloud (R2/Jellyfin) and the explicit "play the 4K original" toggle stay deferred;
every abstraction is chosen so they're "add one resolver / one role," not a rewrite.

## 2. Hard scope boundaries (do not exceed)

**In scope (v2.3):**
- **Footage sidecar** — per-dive `*.footage.json`, JSON-parsed, holding all video
  data (videos list, clips, sources). Read-fallback / write-forward migration.
- **Stable dive `uid`** — immutable handle in dive frontmatter; the sidecar joins on it.
- **Custom-species registry** — stable `customId` for free-text species, with
  autocomplete reuse; clips key onto `scientificName || customId`.
- **`sources[]` per clip** — `{ role, kind, ref }` list behind `resolveVideoUrl`.
  In v2.3 a clip carries `kind:'local'` sources of `role:'proxy'` (the playable
  working copy) and `role:'original'` (archival pointer — the master's filename on
  whatever drive). `resolveVideoUrl` prefers proxy.
- **Local proxy support** — the app generates a **downloadable double-click script**
  (`make-proxies.command`) that runs the user's local ffmpeg over a folder of
  originals (re-encode only, identical timeline); run once per trip, then point the
  app at the proxies folder and tag against them. The app never transcodes itself.
  This is what makes reviewing a ~300 GB trip on a laptop feasible (~10–15 GB of proxies).
- **Desktop video modal** — full-screen, two modes:
  - **Tag** — video list · player + scrubber (IUCN-coloured markers) + transport
    + Mark-reviewed · tagged-in-this-video; `[＋ Tag here]` transforms the right
    column into the **reused** species picker → species + note + R/O/C → Save.
  - **Watch** — same player; right column **animal-first** (each species → its
    clips across every video; tap a clip → load + seek).
  - **Tag ⇄ Watch toggle** above the right pane; entry glyph sets the default.
- **Local player** — HTML5 `<video>`, File System Access API, `currentTime`
  seek-to-timestamp.

**Out of scope — do not implement (deferred):**
- ❌ **The explicit "play the 4K original" toggle** — needs the master mounted and
  chokes decoders; the whole point is to review off proxies. (Resolver *may* fall
  back to an original if its drive is mounted and no proxy exists, but there's no
  user-facing quality switch.)
- ❌ Cloud upload / Cloudflare R2 / Stream (`kind:'r2'` reserved, not built).
- ❌ Jellyfin resolver (`kind:'jellyfin'` reserved, not built). Note: when the
  remote brief lands it will serve **proxies**, not masters — Jellyfin chokes on
  the 4K originals.
- ❌ **Any mobile video UI** — desktop-only this version.
- ❌ In-browser transcoding (ffmpeg.wasm).
- ❌ MP4 container parsing (duration/GPS track), thumbnail generation.
- ❌ Any change to OBIS export, Stats, Log, or the species DB array.
- ❌ Rebuilding the species picker — **reuse the shipped one** (`spBuildPanel` /
  the footage photo-grid picker), only host it in the transformed column.

If you reach for any of the above, **stop and confirm with the user.**

## 3. Architectural constraints (carry-forward)

Non-negotiable.

- **Classic ordered `<script src>` files. NO ES modules.** New logic: `js/video.js`
  (sidecar I/O + `resolveVideoUrl` + player component); `js/footage.js` rebuilt
  for the Tag⇄Watch modal. Functions stay global; inline `onclick=` keeps resolving.
- **No build tools, no backend.** Vanilla browser APIs only.
- **Single-purpose, bisectable commits** — one per phase, each smoke-testable.
- **Service-worker lockstep:** new file → `sw.js` `SHELL` += path, `CACHE` bump.
  Pure edits still bump `CACHE`.
- **Desktop-gate the video UI.** The modal mounts only at the desktop breakpoint
  (≥900px, matching v2.2). Below it, the footage entry points are hidden — there's
  no mobile video. The *data layer* (uid, registry, sidecar) is platform-agnostic
  and works everywhere.
- **Dual store:** localStorage primary on mobile. The **registry** mirrors to
  localStorage (free-text logging happens on mobile). The **footage sidecar** is a
  vault artifact read on desktop; mobile never needs it (nothing to play).
- **`file://` is not a target** (local server in dev, Cloudflare Pages in prod).
- **Offline-first:** local player + sidecars work offline.
- **Portability is the product.** Sidecar + registry are plain JSON, inspectable,
  no lock-in. This is the *reason* for the design, not a cost to hide.
- **Colour/design system:** reuse only. Scrubber markers use the **IUCN red-list
  ramp** already defined for `.iucn` chips (CR violet-deep, EN violet-soft, VU
  gold, NT/LC/DD dim; free-text = dashed pending ring). Buttons use the existing
  `.fm-btn`/`.fm-btn.primary` accent — **no new green**. Type scale unchanged.
- **Wrapper-ready, but no wrapper.** A future **Tauri app (one toolchain for
  desktop *and* mobile)** will bundle ffmpeg and turn proxy generation into one
  button (see ROADMAP.md → "Desktop + Mobile App (Tauri)" and DECISIONS.md). v2.3
  must stay one codebase that simply *allows* that later: isolate the
  proxy-generation step behind a `transcodeProxies()` capability (browser = "emit a
  download script", §2.38) so a Tauri shell can swap in "run the bundled binary"
  with no change to tagging/sidecar code — exactly as `resolveVideoUrl` isolates the
  source backend. Do **not** add any build step or native code now; the browser
  build stays the source of truth.

## 4. The foundation: stable identity (do this first, it underpins everything)

The split only works if references survive renames and edits. Two stable ids.

### 4.1 Dive `uid` — immutable handle in frontmatter
**Problem:** `frontmatterToDive` (markdown.js:134-138) hashes the filename into
`dive.id`, so synced dives' ids change on rename. Sidecars can't join on that.

**Decision:** add `uid` to dive YAML frontmatter — minted once, **never derived**
from filename/date/anything mutable. Format: `dl_<base36 random>`. In memory on `dive.uid`.

- **Generate:** on save of any dive lacking one (`saveDive`), backfill on import.
- **Join:** the sidecar stores `"diveUid"`. App builds `Map<uid, footage>` on load.
- `dive.id` stays for in-memory keying/DOM; `uid` is purely the cross-file link.
  Do **not** rip out `dive.id`.

### 4.2 Custom-species `customId` — stable key for free-text
**Problem:** clips key onto `scientificName || commonName`. Free-text species have
no `scientificName`, and `commonName` is mutable — fix a typo and every clip
orphans. (Also a latent bug today: "Hairy frogfish" and "hairy frogfish" are two
different species in the album.)

**Decision:** a **custom-species registry** assigns each free-text species a stable
`customId` (`cs_<base36>`), minted on first entry.

- Clip join key becomes `scientificName || customId` (one-line change to the
  pattern `buildSpeciesIndex` in `album.js` already uses).
- `customId` stored **on the sighting in the dive MD** (free-text entries only — DB
  species keep `scientificName`/`aphiaId`), so the record stays self-contained.
- Registry doubles as: (a) autocomplete for repeat free-text entries, (b) the
  future home for OBIS `aphiaId` resolution.

```jsonc
// custom-species.json  (vault root; mirrored to localStorage)
{ "cs_k2a9": { "commonName": "Hairy frogfish", "scientificName": "",
               "group": "Fish", "aphiaId": null } }
```

**Locked: asymmetric key** — DB species on `scientificName`, free-text on
`customId` (smaller change, matches today's `||`). Unify later only if it bites.

## 5. Data model

### 5.1 Footage sidecar — one JSON file per dive with footage
```jsonc
// dive-128-batu-balong.footage.json  (basename matches the .md for findability;
//                                      the app joins on diveUid, not the name)
{
  "diveUid": "dl_k9f3a2x",
  "videos": [
    { "file": "GX010128.MP4", "proxy": "proxies/GX010128.mp4",
      "modified": 1715600000000, "size": 4500000000, "reviewed": true }
  ],
  "clips": {
    "Eretmochelys imbricata": [           // key = scientificName || customId
      { "time": "06:12", "note": "close pass",
        "sources": [
          { "role":"proxy",    "kind":"local", "ref":"proxies/GX010128.mp4" },
          { "role":"original", "kind":"local", "ref":"GX010128.MP4" }
        ] }
      // future: additional sources { kind:"r2"/"jellyfin" } — not v2.3
    ]
  }
}
```

- **JSON, not YAML** — `JSON.parse()`, zero custom parser. The whole point: the
  nested-YAML reader in `markdown.js` is **frozen** and reverts to reading only the
  simple, stable species list.
- `videos[]` shape carries forward from today's in-memory shape (footage.js:187):
  `{ file, modified, size, reviewed }`. `reviewed` stays a **manual** toggle, never
  auto-derived (carry-forward from the v2.0 decision).

### 5.2 `sources[]` — host-agnostic clip locations
- `role`: `"proxy"` (the small working copy you review/tag from) and `"original"`
  (the archival master pointer). v2.3 uses both, `kind:'local'`.
- `kind`: `"local"` in v2.3. (`"r2"`, `"jellyfin"` reserved for the cloud brief.)
- `ref`: meaning is per-`kind` (local path now; object key / item id later).
- `resolveVideoUrl` **prefers `proxy`**, falling back to `original` only if no proxy
  exists and the original's drive happens to be mounted.
- **Proxy↔original share an identical timeline** — proxies are re-encode-only
  (scale/bitrate down, never re-time/trim), so a timestamp tagged on the proxy is
  frame-valid on the master. This invariant is load-bearing — document it where the
  ffmpeg command is generated.
- The array exists so the cloud brief adds `r2`/`jellyfin` entries without reshaping data.

### 5.3 What stays in the dive `.md` (precious, unchanged parser)
Species, abundance (R/O/C), `aphiaId`, `validated`, `group`, and now `uid` +
(free-text only) `customId`. **No clips, no videos, no sources in the MD going
forward.** Dataview/OBIS queries unaffected.

## 6. Migration — backward-compatible, no big-bang

- **Read:** for each dive, look up its sidecar by `diveUid`; if absent, fall back
  to the clips still embedded in the old MD (`_sightingClips` already normalises
  the legacy `{video,time}` and `clips[]` shapes — reuse it).
- **Write:** footage edits write **only** to the sidecar (+ localStorage mirror of
  the registry). The MD species list is written without any clip/video keys.
- **uid backfill:** when a legacy dive (no `uid`) is saved or has footage edited,
  mint a `uid`, write it to the MD frontmatter, create the sidecar. Untouched old
  dives keep working via read-fallback.
- **`deleteDive`** must also delete the matching sidecar (one line) — avoids orphans.
- Optional later cleanup pass strips now-ignored clip keys from migrated MDs.

**Honest cost:** two files can desync (delete orphans a sidecar). Mitigated by
delete-both + graceful "missing sidecar = no footage." Accepted because it removes
the parser-churn blast radius from the precious biological data.

## 7. The player seam

```
resolveVideoUrl(clip|video, { prefer = 'proxy', allowKinds = ['local'] }) -> string | null
```
- v2.3 resolves `kind:'local'` → an object URL from a File System Access handle.
  Picks by preference order: **proxy first**, original only as a fallback when no
  proxy exists and the master's drive is mounted. Returns `null` (graceful "footage
  not reachable here") when nothing resolves — the normal case being the proxies
  folder hasn't been pointed at yet.
- **Single choke point** so the cloud brief adds `r2`/`jellyfin` cases here and
  nowhere else.

Player mechanics (local): HTML5 `<video>`; set `currentTime` after
`loadedmetadata`; transport = play/pause, ±5s scrub, frame-step (Tag only),
chapter-skip (⏮⏭ between this video's tagged moments). Timestamp is shown on the
video surface, not duplicated in the transport.

## 8. UI specification (the locked mockup → build target)

Open `mockups/mockup-video-modal.html`. **Desktop-only**, full-screen modal
(`max-width:1500px`, tall fixed body, columns scroll internally so the two modes
are the same height with no whitespace). Header: `🎬 Footage · <dive context>` +
`✕`. The **Tag ⇄ Watch toggle sits in a bar above the right pane** (not the header
— the dive site name needs the header width).

### 8A. Shared player (centre column, both modes)
- Video surface (16:9) with filename label + live timestamp overlaid.
- **Scrubber with IUCN-coloured markers** — one dot per tagged moment, coloured by
  the sighting's IUCN status (CR/EN/VU/NT-LC-DD ramp; free-text = dashed pending
  ring). This is the signature element shared by both modes; markers are
  clickable → seek.
- Transport differs by mode (see below). No timestamp text in the transport.

### 8B. Tag mode (`mockup` panels 1 & 2)
- **Left:** video list — filename, duration, review dot (green=reviewed,
  amber=not), tag count, "N left" counter, "＋ Add videos…". Scrolls internally.
- **Centre:** player; transport = ⏮ play ⏭ · ‹‹5 5›› · frame-step ◀| |▶ ·
  `[＋ Tag here]`; **Mark-reviewed** toggle bottom-right (manual; drives the
  list dots).
- **Right, default:** "Tagged in this video" — moment rows, each with a **`▶ jump`
  pill** (seek) distinct from the **editable body** (`✎` species + note, tap to
  edit inline). IUCN chip on the right.
- **Right, after `[＋ Tag here]`:** the column **transforms in place** (player +
  list stay live; the tag button shows "Tagging…"). Order top→bottom:
  1. **Already-logged pills** — single horizontal-scroll row in an accent-tinted
     band ("tap to link" an existing sighting at the current time).
  2. **Category tabs** — the shipped picker's tabs.
  3. **Option-B browse** — full-width ~208px photos (the chosen ID-friendly
     layout), ~1.5 in view. Selection = outline, not a pre-filled label.
  4. **Bottom zone (all typing clustered here):** `🔍 Search species` (filters the
     grid) · `✎ Add a note` · compact `Abundance R/O/C` · `Cancel` + `Save
     sighting` (`.fm-btn.primary`). Picking a species does **not** auto-advance —
     you set note + abundance first.
- **Reuse**, don't rebuild, the species photo-grid + search engine; only its
  container (the transformed column) is new.

### 8C. Watch mode (`mockup` panel 3)
- Same player; transport = ⏮ play ⏭ · ‹‹5 5›› only (no frame-step, no tag button,
  no reviewed toggle). ⏮⏭ skip between this dive's moments.
- **Right: animal-first.** Taxon-grouped (same order as the species album), each
  species row = thumb · name · sci · IUCN chip · `▶ N` clip count. Tap a species →
  expands to **its clips across every video of the dive** (video name · note ·
  timestamp). Tap a clip → player loads that video and seeks. This surfaces the
  existing multi-clip model (one animal, many clips, many videos).

### 8D. Entry points + mode (reconciles the v2.2 glyph split)
From the dive file (desktop):
- **🎬 ("manage footage")** → opens the modal in **Tag** mode.
- **▶ on a species** (in the marine list) → opens the modal in **Watch** mode,
  pre-expanded to that animal. **▶ becomes functional here** — this fulfils the
  v2.0 deferral ("▶ becomes a play button when playback ships"). It was passive in
  v2.2 only because playback didn't exist yet; 🎬 remains the manage action.
- Inside, the **header-adjacent toggle** flips Tag ⇄ Watch without closing (data,
  player, video are identical; only the right column + transport change). Tag
  first, Watch second.

## 9. Implementation phases (one commit each: `2.31 … 2.38`, then `2.4`)

Foundation/data phases (2.31–2.34) are platform-agnostic; UI + proxy phases
(2.35–2.38) are desktop-gated.

### 2.31 — Stable dive `uid`
Add `uid` to the data model, frontmatter read/write (`markdown.js`), mint-on-save
(`app.js`), backfill-on-import. No behaviour change otherwise.
*Smoke:* new + edited + imported dives gain a stable `uid` that survives a filename change.

### 2.32 — Custom-species registry + `customId`
Registry file + localStorage mirror; mint `customId` on free-text entry; store on
the MD sighting; autocomplete from registry; album join → `scientificName ||
customId`.
*Smoke:* same free-text name across two dives unifies in the album; renaming its

### 2.33 — Footage sidecar (read-fallback / write-forward)
`js/video.js`: sidecar load (`Map<uid, footage>`), write, delete-with-dive.
Footage data reads sidecar-first, falls back to MD clips; writes only the sidecar;

*Smoke:* existing footage still shows; a new clip lands in the sidecar not the MD;

### 2.34 — `sources[]` model + `resolveVideoUrl`

*Smoke:* clips round-trip through `sources[]`; resolver returns a URL for a

### 2.35 — Modal shell + player core (desktop)
Full-screen modal; left video list (switch videos, review dots, counts); centre

*Smoke:* open modal, switch videos, scrub, markers appear at tagged times, click a
marker → seek; hidden below the breakpoint.

### 2.36 — Tag mode
Right column "tagged in this video" (jump pill vs editable body); `[＋ Tag here]`

R/O/C; Save writes a sidecar clip; already-logged link pills; Mark-reviewed toggle.
*Smoke:* tag a species mid-review → persists to sidecar, marker appears, dot/counts
update; edit a note inline; link an already-logged species.

### 2.37 — Watch mode + Tag⇄Watch toggle + entry glyphs
Animal-first right column (species → clips across videos → seek); the toggle bar;
dive-file entry glyphs (🎬→Tag, ▶→Watch pre-expanded). Watch transport (no
tag/frame controls).
*Smoke:* enter via each glyph into the right mode; toggle flips without closing;
animal → clip → player loads + seeks.

### 2.38 — Local proxy workflow
The piece that makes a ~300 GB trip reviewable on a laptop. **The app never
transcodes** (no backend, ffmpeg.wasm rejected) — it *directs* the conversion the
user runs locally.

- **"Generate proxies" → a downloadable double-click script.** Implement behind a
  `transcodeProxies()` capability seam (so a future Tauri shell can swap
  this for a bundled-ffmpeg call — see §3). In the browser, the capability builds a
  `make-proxies.command` (macOS; `.sh` elsewhere) the user double-clicks — no
  terminal. The script runs the user's installed ffmpeg over a folder of originals,
  re-encode only (scale + bitrate down, e.g. 720p H.264, **timeline untouched**),
  writing a sibling `proxies/` folder. Include a one-line "needs ffmpeg installed
  (`brew install ffmpeg`)" note in the affordance.
- **Then point the app at the `proxies/` folder** (File System Access — same
  mechanism as the existing folder sync). The app matches proxies to videos by
  filename and records both `proxy` (working copy) + `original` (archival pointer)
  sources. Originals never move or upload.
- `resolveVideoUrl` already prefers proxy (2.34), so playback + tagging now run off
  the small files; tagged timestamps stay frame-valid on the masters.

*Smoke:* download the script, double-click it on a folder of clips, get a
`proxies/` folder; point the app at it; play + tag off the proxy; confirm a tagged
timestamp lands correctly when checked against the master.

### 2.4 — Polish + docs + version stamp
Empty/edge states (no source reachable; missing sidecar; a dive with no videos;
file handle lost → re-grant prompt). Inline-handler grep. Update `CLAUDE.md` (data
model: `uid`, sidecar, registry; footage modal is desktop-only Tag⇄Watch), add a
`DECISIONS.md` section, stamp `CHANGELOG.md` → `## [2.4]`.
