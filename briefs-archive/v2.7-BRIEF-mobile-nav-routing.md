## 1. The job to be done

Two related mobile-UX gaps, one underlying cause (the app has **no browser
history integration** — navigation just flips `.active` classes via
`show(name, btn)` in `js/app.js`):

1. **The Android back gesture exits the PWA instead of going back.** Switching
   panels and opening overlays (dive file, species profile, footage modal)
   push nothing onto the history stack, so the system back gesture pops the
   single initial entry and leaves the app. This is the dominant interaction
   model on the primary target platform.

2. **The species page is a dead-end.** From a species profile ("dives where I
   saw a cuttlefish") you cannot jump to the dive or its footage — you must
   back out to History and hunt for the dive manually. The footage clip rows
   in the species modal are passive text (`<div class="sp-video-ref">`, no
   handler).

The fix makes in-app navigation **history-aware** (back gesture works, root =
home, back-at-root correctly exits), and adds the **species → dive / footage**
links that the history integration makes safe to build.

## 2. Hard scope boundaries (do not exceed)

- **Hash routing for the five panels only** — `#log` (home/default),
  `#history`, `#species`, `#stats`, `#data`. **No real paths** (`/history`):
  those would need a Cloudflare Pages SPA fallback *and* service-worker
  navigation-fallback logic on the SW we just hardened for Access — all
  avoided by hash. (`file://` is a non-goal and plays no part here.)
- **Overlays are state-only history entries, NOT URL-addressable.** Dive file,
  species profile, and footage modal get `pushState` entries so back closes
  them — but no `#…/dive/123` deep-link scheme. Deep-linking is the deferred
  Option D; the nav seam below makes it a drop-in later without touching call
  sites.
- **One history mechanism.** A single `popstate` handler is the source of
  truth. Do not also drive routing from `hashchange`. Do not introduce a
  router library.
- **No visual redesign.** This is plumbing + two link affordances. Panels,
  modals, and the dive-file view render exactly as today.
- **No build tools / no ES modules** — classic ordered `<script src>`,
  functions stay global (carry-forward).

## 3. Architecture: one declarative back model

Every navigation the user would expect "back" to undo pushes **one** history
entry whose `state` records the **full intended UI**, e.g.
`{ panel: 'species', overlay: null }` or
`{ panel: 'species', overlay: { type: 'footage', diveId: 123, mode: 'watch', key: 'Sepia officinalis' } }`.
The single `popstate` handler reads `event.state` and **reconciles the DOM to
match it** — switch panel if different, open/close the overlay to match. This
declarative "render the target state" approach is far more robust than
imperative "pop one thing" logic.

Two layers:

- **Layer 1 — panel** is reflected in the hash (`#history`), so refresh and
  reload land on the right panel.
- **Layer 2 — overlay** is a state-only entry pushed *on top of* the current
  panel state. Back pops it and the panel underneath is exactly as it was
  (scroll included).

### The nav seam (the "settle the architecture" deliverable)

Introduce thin primitives that all navigation routes through — today they wrap
the existing functions; later they can become route-backed with no call-site
changes:

- `goPanel(name)` — sets the panel hash + pushes/replaces the panel entry,
  calls the btn-less `show(name)`.
- `openOverlay(spec)` / `closeTopOverlay()` — push/replace overlay state and
  open/close the matching overlay (`openDiveFile`, `openSpeciesProfile`,
  `openFootage`).

## 4. Wrinkles to handle (identified during analysis — not surprises)

1. **Scroll-anchor collision.** The species catnav uses `href="#cat-fish"`
   anchors for in-page scrolling (`js/album.js`). The router must only treat a
   known set of panel hashes as routes and ignore `#cat-*` (and any other
   in-page anchors), or those taps will be misread as panel changes.
2. **Convert the 5 nav links to JS `goPanel()` calls** instead of relying on
   `<a href="#…">`, to avoid double-firing and to keep one code path.
3. **`show(name, btn)` needs a btn-less variant** — `popstate` has no button;
   `show(name)` should derive the active nav button from the name.
4. **Normalise the initial entry** with `replaceState` on load (empty hash →
   home) so there's a clean base and refresh-on-hash works.
5. **Body-scroll lock bug (latent today).** Species and footage modals each
   independently set `document.body.style.overflow` on open and reset it to
   `''` on close. With overlays stacked, closing the top one wrongly unlocks
   scrolling while another is still open. Centralise the lock: locked while
   **any** overlay is open, restored only when the last closes.
6. **Escape unified with back.** Both modals have their own Escape handlers.
   Route Escape through `closeTopOverlay()` (= `history.back()` when an overlay
   is open) so keyboard and gesture share one path and only pop the top.
7. **Free-text key mismatch (carry-forward from album fix).** The album
   indexes free-text species by `customId`, but footage matches the watch key
   on `m.scientificName || m.customId` (and free-text stores the typed text in
   `scientificName`). When wiring species → footage watch, pass the
   footage-compatible key, and normalise free-text key handling at the seam so
   the right species expands in watch mode.

## 7. Decision log (locked — do not re-litigate)

- **Hash routing, not real paths** — zero server/SW changes, offline-safe;
  real paths' only win (shareable URLs) is near-worthless for a personal,
  no-server, behind-Access app. file:// is irrelevant to this (non-goal).
- **Overlays state-only, not URL-addressable** — deep links are the deferred
  Option D; the seam makes them a later drop-in.
- **One `popstate` source of truth, declarative full-state entries** — not
  imperative pop logic, not dual hashchange+popstate.
- **Wrapper-agnostic** — identical under Tauri; does not block or depend on
  the v2.5 desktop work.
- **Defer Option D (full deep-link router)** until a concrete need appears
  (e.g. the Species Pokédex turning the app into a dense cross-linked web).
- **Footage modal is Tauri-app-only (the video workspace); web/mobile watching is
  the separate v2.8 player** — the app is the workspace; the web is logging +
  (later) watching. See §8. Reshapes 2.73's footage half to Tauri-only.

## 8. Footage modal = Tauri-only workspace (web-vs-app split)

**Decision (locked):** the footage modal *is* the **video workspace** and runs in the
**Tauri app only** (`isShell()`) — it uses the macOS Apple/VideoToolbox encoder to create
proxies, which a browser can't do reliably. The web build (mobile *and* desktop browser)
never opens it. **For now footage is Tauri-only end to end — both tagging *and* watching**
— because the videos are local files only the app can reach. The interim gating is
deliberate: footage is a power-user layer, surfaced only after users get value from the
core (logging, species, history, stats), which stay cross-platform.

**Cross-platform watching is a future capability gated on cloud hosting** (Backblaze B2 or
a pluggable provider). End-state: Tauri stays the tagging + proxy workspace; the browser
and mobile become *viewers* that stream tagged species' footage from the cloud. The v2.8
species-profile player is **Tauri-scoped initially** and becomes the cross-platform viewer
only once that cloud layer exists.

**Gate:** `openFootage()` and every footage entry point ⇒ `isShell()` only. On web, hide:
- timeline card 🎬 (`history.js` dh-abtn), dive-file app-bar 🎬 (df-action-btn), and the
  dive-file desktop "🎬 Footage" button (df-desk-abtn);
- the mobile footage picker (`#footage-mob-picker`);
- the ▶ watch-mode entries that open the modal from species clip rows.

**Ripples:**
- **v2.65:** the ever-present greyed 🎬 just shipped is a workspace entry → on web it must
  be **hidden**, not greyed. "Greyed-when-empty" becomes a Tauri-only behaviour (wrap those
  buttons in `isShell()`).
- **2.73 (this brief):** the species→footage *watch* link uses the modal, so it becomes
  **Tauri-only**; on mobile, species→footage watching waits for the v2.8 player. The
  species→**dive** link (2.73's other half) is unaffected.
- **v2.8:** its species-profile player is **Tauri-scoped initially** (watch tagged footage
  in the app); it becomes the cross-platform viewer only with the future cloud layer.

**Implementation:** small — an `isShell()` gate on `openFootage()` plus hiding the entries
above. Land as its own phase (**2.67b**) or alongside 2.72.
