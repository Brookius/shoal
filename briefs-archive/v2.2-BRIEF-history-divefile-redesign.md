this once end-to-end before touching code. The mockups it references **are**
the visual specification — open them in a browser:

- `mockups/mockup-history-mobile.html` — the History timeline cards. **Direction

- `mockups/mockup-dive-file-tabbed.html` — the opened dive ("dive file") on
  **mobile**: full-screen, tabbed (Marine / Overview / Notes), opening on Marine.

## 1. The job to be done

The History view's job is **navigation** — find one dive among 200+ and dip into
it. Today's timeline rows are cramped on mobile and the dive expands *inline*
under the trip (you scroll past the whole trip to read one dive, and you must
scroll to the very bottom to reach Edit). The opened dive wastes space on mobile
and the dive-data block is hard to scan.

This redesign delivers:
1. A richer, more legible **History card** (mobile stacked / desktop horizontal)
   that carries the dive's identity, signature stats, and the rarest species seen.
2. A **full-screen "dive file"** that replaces the inline expand — opening a dive
   is a navigation step (with a back affordance), not an accordion.
3. **Edit always reachable** from the top of the dive file (no scroll-to-bottom).
4. The marine-life **species album** given full width; dive data presented in
   clean white-container cards.

**No data-model changes.** This is a presentation + navigation redesign over
existing dive objects and the existing species album engine.

## 2. Hard scope boundaries (do not exceed)

**In scope (v2.2):**
- Redesigned History timeline card — mobile (stacked) + desktop (horizontal),
  with a responsive breakpoint between them.
- Coloured **spine** carrying the dive type as a vertical word (replaces the
  inline coloured type *word* in today's `.tl-meta`).
- **Rarest-species** thumbnail + name (desktop) / thumbnail + count (mobile) on
  each card, derived from existing sightings.
- Dive file as a **full view** (mobile full-screen takeover; desktop content-area
  view), replacing the inline `.tl-detail` expand.
- Mobile dive file: **segmented tabs** Marine / Overview / Notes, opening on Marine.
- Desktop dive file: **two columns** (marine album left + notes; data cards right),
  no tabs.
- **Location map** on the dive file (single marker) — reuses `loadLeaflet()`.
- Trip header restyle + optional **trip map strip** (see Phase 7 — may ship later).
- Glyph semantics: **🎬 = "manage footage" action**; **▶ = passive "videos linked"
  indicator**. Apply consistently.
- Quick **Edit** (and Delete/Footage) reachable without opening/scrolling.

**Out of scope — do not implement (deferred / unchanged):**
- ❌ Any change to the species album engine itself (`spBuildPanel`, carousel,
  taxon list logic). It is **kept as-is** — only its container/width changes.
- ❌ Video playback (still v2.1+ territory; ▶ stays passive).
- ❌ Personal photos (v3.1).
- ❌ Changes to the data model, frontmatter, or sync.
- ❌ New sort modes or filters.
- ❌ Reworking the Footage modal (opened by 🎬 — unchanged internally).
- ❌ Stats / Species / Log / Data panels.

If you reach for any of the above, **stop and confirm with the user.**

## 3. Architectural constraints (carry-forward)

Non-negotiable. Read `DECISIONS.md → "Modular migration"`.

- **Classic ordered `<script src>` files. NO ES modules.** Functions stay global.
  History/dive-file logic lives in `js/history.js`; reuse `js/album.js`
  (`_iucnRank`), `js/species.js` (`SP_PHOTO_MAP`, `SP_IUCN_MAP`, `GROUP_EMOJI`),
  `js/map.js` (`loadLeaflet`). Inline `onclick=` handlers must keep resolving.
- **No build tools.** Vanilla browser APIs only.
- **Single-purpose, bisectable commits** (one per phase). Each independently
  smoke-testable. No automated tests — discipline is the net.
- **Service-worker lockstep**: if you add a file → `SHELL` += path, `CACHE`
  bump (`divelog-v19` → `v20`). Pure edits to existing files still need a `CACHE`
  bump so the SW serves fresh JS/CSS (the v2.0 brief documents this trap).
- **Colour system v2** (`CLAUDE colour UI.md`): reuse only.
  - Dive-type spine uses the existing `--type-*` ramp. **The palette itself is
    flagged for a separate future revisit — do not change the values now.**
  - ▶ indicator + 🎬 action + the SAC-good figure use `--accent` / `--success`
    per current usage. No new reserved colours.
- **Type scale** (`--text-xs/sm/base` = 12/14/16). The mockups use a few raw
  display sizes for hero numbers (18–26px) — those are intentional display
  figures (same exception the Stats hero numbers already use). Everything else
  must use the scale. **Do not introduce off-scale body sizes (11/13/15/17).**
- **Offline-first**: Leaflet tiles require network. Maps must **degrade
  gracefully** (hide the map container) when offline or when a dive/trip has no
  GPS — never render an empty/broken map box.
- **`file://` is no longer a target.** The app now runs from a local server in
  dev and Cloudflare Pages in prod. (Update `CLAUDE.md → Known constraints` in
  the docs phase — the "Must work from `file://`" line is stale.)

## 4. Derived data — the only new computation

No schema changes. One new helper, plus reuse of the album index.

### 4.1 Rarest sighting per dive
Add to `js/history.js` (or `js/album.js` if more natural — it already has
`_iucnRank` and the photo maps are in `species.js`):

```js
// Returns the single "standout" sighting for a dive's card, or null.
// Rarest by IUCN (CR>EN>VU>NT>LC>DD>unknown), tie-break by group order
// then commonName. Reuses _iucnRank() from album.js.
function rarestSighting(dive) {
  const marine = dive.marine || [];
  if (!marine.length) return null;
  return marine.slice().sort((a, b) => {
    const r = _iucnRank(SP_IUCN_MAP[b.scientificName]) - _iucnRank(SP_IUCN_MAP[a.scientificName]);
    if (r) return r;
    return (a.commonName || '').localeCompare(b.commonName || '');
  })[0];
}
```

The card thumbnail uses `SP_PHOTO_MAP[sighting.scientificName]` (square variant),
falling back to the `GROUP_EMOJI` placeholder when absent — exactly as the album
list rows already do (`spRowHtml`).

### 4.2 Species count / footage count
`dive.marine.length` for `🐟 N sp.`; distinct linked videos for the `▶ N`
indicator — reuse the existing timeline footage computation in `renderTlRow`
(`new Set(marine.flatMap(m => _sightingClips(m).map(c => c.video))).size`).

## 6. UI surfaces (visual spec → mockups)

### A. History timeline card — MOBILE (`mockup-history-mobile.html`, Direction D)

Replaces `renderTlRow`'s markup + `.tl-*` CSS. Per card:
- **Spine** (left, ~26px, full height): dive type as vertical mono caps,
  background = `--type-<Type>`. White text. This *is* the type label — remove the
  coloured type word from the meta row.
- **Identity** (top-left of content): site name (hero, `--text-base`/700) with
  inline 📍 when GPS present; date (mono `--text-xs` muted); dive# (`#149`, mono
  `--text-sm`/600). Stacked, three lines.
- **Measurements** (top-right): a 3-row CSS grid — icon column (↓ ⏱ 👁) | number
  (right-aligned, `font-variant-numeric: tabular-nums`) | unit. All numbers share
  the middle column so they align vertically. **Vis is muted by colour** (not
  size) to demote it.
- **Divider**, then **marine row** (full width): rarest-species thumbnail (~52px) +
  `🐟 N sp.` and, when footage exists, `▶ N` (accent). A **quick-edit ✎** button
  sits at the right of this row.
- No species *name* on mobile (truncates uselessly — name is desktop-only).

Trip grouping unchanged in logic (`groupDivesByTrip`). Trip header restyle →
Phase 7.

### B. History timeline card — DESKTOP (`mockup-desktop.html`, History window)

Above the responsive breakpoint, the card **unfolds horizontally** into one
strip (CSS grid):

`spine │ identity │ ↓depth │ ⏱time │ 👁vis │ rarest species │ actions`

- Fixed-width measurement columns so values **align vertically across stacked
  cards** (table-like).
- Identity compresses to two lines: site (hero) / `#148 · date`.
- Marine cell shows the **species name** (desktop has room) + `🐟 N sp.` + `▶ N`.
- **Action cluster** (right): `🎬 footage` (only when videos) · `✎ edit` ·
  `🗑 delete`. Delete uses the rust hover state.
- Responsive breakpoint: **≥ ~900px** content width → horizontal card; below →
  the mobile stacked card. Implement as a media query on the History panel /
  card classes. (No third intermediate layout.)

### C. Dive file — navigation change (both platforms)

**This is the biggest structural change.** Today `toggleDiveMD(id)` injects
`renderDiveDetail(d)` into an inline `.tl-detail` under the row. Replace with a
**full view**:

- New `openDiveFile(id)` / `closeDiveFile()` in `js/history.js`.
- Opening a dive **hides the History list** (timeline + sort toolbar + panel head)
  and renders the dive file into `#panel-history` (or a dedicated child
  container). On mobile this is a full-screen takeover; on desktop the sidebar
  persists and the content area shows the dive file.
- A **back affordance** returns to the timeline, restoring scroll position
  (capture `scrollY` on open, restore on close).
- Route through the existing `show()` mechanism where sensible, **but do not add
  another patch to `show()`** (CLAUDE.md rule) — keep dive-file open/close as its
  own functions called from the row click + back button.
- Remove the inline-expand path (`toggleDiveMD`, `.tl-detail`, the per-row
  `dive-card-md`) once the full view works. Keep `renderDiveDetail`'s *content
  builders* (marine album, data rows) — they're reused inside the new view.

### D. Dive file — MOBILE (`mockup-dive-file-tabbed.html`)

- **App bar**: `‹` back · trip name (mono, muted) · `🎬` (manage footage, accent)
  · `✎` (edit) · `⋯` (more: delete / download `.md`).
- **Hero**: type pill · site (hero) · `#148 · region, country · date`.
- **Persistent stat band** (stays across tabs): depth / time / vis, 3-up white
  container. **Keep it pinned** (decision locked with the user).
- **Segmented control**: `Marine N` · `Overview` · `Notes`. **Default = Marine.**
- **Marine tab**: the existing species album (carousel hero + taxon list), full
  width. Reuse `spBuildPanel` output — just host it full-bleed.
- **Overview tab**: dive data as **full-width stacked white cards** — Conditions,
  Profile, Gas & equipment. Full-width stacking is deliberate: it avoids the
  uneven-height problem of side-by-side tiles when field counts differ.
- **Notes tab**: Notes write-up card + Sign-off card (buddy / operator / trip /
  cert). When a dive has neither notes nor sign-off, **hide the Notes tab**
  (don't show an empty tab).

### E. Dive file — DESKTOP (`mockup-desktop.html`, Dive file window)

Tabs **dissolve into columns** — everything visible at once:
- **Back link** (`‹ Back to <trip>`).
- **Header row**: type pill · site · meta, with action buttons right-aligned:
  `🎬 Footage N` · `✎ Edit` · `⋯`.
- **Wide stat band** (5-up, desktop affordance): max depth · bottom time · vis ·
  avg depth · **SAC** (`--success` when good). (Mobile keeps SAC in the Gas card;
  desktop promotes it to the band because there's room.)
- **Two columns**:
  - **Left (~1.45fr)**: Marine album (taller hero) **+ Notes card underneath it.**
  - **Right (~1fr)**: **Location map card** (top) + dive-data cards (Conditions,
    Gas & equipment, Profile · Sign-off).
- **Notes lives under marine life** (left column), not in the data column — locked.

### F. Location map (dive file, both platforms)

- A "Location" card with a single marker at the dive's `gps_lat/gps_lng`.
- Reuse `loadLeaflet()` from `js/map.js`; `setView([lat,lng], ~11)` + one marker.
- **Hide the entire card** when the dive has no GPS or when offline/tiles fail.
- Tear down the Leaflet instance on dive-file close (`.remove()`) to avoid the
  leak documented for the species-profile map (v2.1 fix).
- On mobile this is content inside the **Overview** tab (top), matching the
  desktop right-column placement.

## 8. Edge cases & details to get right

- **Dive with no marine life**: card shows no rarest thumbnail — render a small
  neutral placeholder (group-agnostic) or omit the marine row; don't break the
  grid. Dive file Marine tab shows the existing "no marine life" empty state.
- **Unvalidated / free-text species** (no `scientificName`): `rarestSighting`
  falls back to `commonName`; photo/IUCN lookups miss → emoji placeholder, no
  IUCN. Don't crash on `SP_*_MAP[undefined]`.
- **Tabular alignment**: depth like `8.8` vs `22.9` must right-align — use
  `tabular-nums` and a fixed number column (mobile grid + desktop fixed columns).
- **Quick-edit / action buttons must `stopPropagation`** so they don't also open
  the dive file.
- **Back restores scroll**: capture `window.scrollY` (or the panel's scrollTop)
  on `openDiveFile`, restore on `closeDiveFile`.
- **Leaflet teardown**: every map (dive-file location + each trip map) must
  `.remove()` on close/unmount. Guard re-init.
- **Offline**: `loadLeaflet` may fail or tiles won't load — wrap in try/catch and
  hide the map container; never show a grey broken box.
- **SAC** only shows when `calcSAC` returns non-null (existing accuracy gate) —
  in the band (desktop) or Gas card; hide the cell/row otherwise.
- **Spine text length**: longest type is "Pinnacle" (8 chars) — verify it fits
  vertically in the spine at the card height without clipping.
- **Mobile Notes tab hidden** when no notes AND no sign-off data.
