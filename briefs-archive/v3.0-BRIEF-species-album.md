# v3.0 Brief — Species Album (Layer 1)

**Self-contained implementation brief for a fresh session (Sonnet).** Read
this once end-to-end before touching code. The mockup it references *is*
the visual specification — open it in a browser:

- `mockups/mockup-species-album.html` — the album panel (thumbnail strips
  per taxonomic group, sticky category nav) + the species profile modal
  (hero, Leaflet map, sightings list with video reference).

Also read first: `DECISIONS.md → "Modular migration"`, `CLAUDE colour UI.md`
(the colour system), the README → `index.html` code map, and
`v2.0-BRIEF-video-footage.md` (this brief mirrors that one's structure and
discipline — refer to it when in doubt about process).

---

## 1. The job to be done

The user wants to answer: **"Which dive(s) did I see this animal on?"** —
ideally with the linked video references surfaced alongside. The classic
trigger: *"I want to show someone the video I took of an octopus"* → open
the album → tap octopus → see every dive it was logged on + the linked
GoPro clip + timestamp.

A secondary job is *"See a gallery of species I've recorded"* — visually
satisfying, slightly Pokédex-flavoured, but the answer-finding job is what
the feature is graded on.

**v3.0 ships Layer 1**: the species index built from the existing logged
sightings, using the iNaturalist reference photos already baked into
`SPECIES_DB`. **Personal photos (Layer 2) are explicitly NOT in v3.0** —
deferred to v3.1+ once we've decided whether to add a small backend.

---

## 2. Hard scope boundaries (do not exceed)

**In scope (v3.0):**
- A new top-level **Species** panel (4th panel alongside Log / History /
  Stats — or replacing one of them in nav; see §5A).
- Coverage = **only species the user has logged** (not the full 1,010
  Pokédex). Build the index from `dives.flatMap(d => d.marine)`.
- Thumbnail-strip layout: one section per taxonomic group, alphabetical
  group order, IUCN-rarity sort *within* each strip.
- Sticky category nav strip (anchor links to each group section).
- Search field that filters thumbnails by common or scientific name.
- Species profile modal with hero, "Where you've seen it" Leaflet map,
  and sightings list (most-recent-first), with **passive ▶ video-ref
  rows** when a sighting has `video`/`time` (reuses the per-sighting
  fields already shipped in v2.0).
- Empty state copy locked: *"No species recorded yet — log a dive or
  sync your data."*

**Out of scope — do not implement (deferred):**
- ❌ Personal photo upload / vault-link / Google Photos / Proton Drive
  integration (Layer 2 — deferred to v3.1+)
- ❌ Full 1,010-species Pokédex with undiscovered/greyed-out thumbnails
  (separate roadmap item — keep this album to "logged species only")
- ❌ Deep links from dive cards into the album (user explicitly declined
  in scoping)
- ❌ Photo edit / crop / caption per sighting
- ❌ Sort controls in the album bar (sort is locked to IUCN rarity within
  group; group order is alphabetical)
- ❌ Video *playback* from the album modal (the ▶ row is **passive** in
  v3.0, matching its current passive state on the dive card; playback is
  v2.1+ territory and applies to both surfaces at once when it ships)
- ❌ Tapping the map marker to open the dive (out of scope — markers are
  decorative for v3.0; defer until we know the interaction works on
  mobile without zoom fights)
- ❌ Photo lightbox / full-size view of the iNaturalist hero photo

If you find yourself reaching for any of the above, **stop and confirm
with the user first.**

## 3. Architectural constraints (carry-forward)

These are non-negotiable. Read `DECISIONS.md → "Modular migration"`.

- **Classic ordered `<script src>` files. NO ES modules.** New JS goes in
  `js/album.js`, loaded before the main inline `<script>` (and after
  `js/species.js`, since it reads `SP_PHOTO_MAP`/`SP_IUCN_MAP`/
  `GROUP_EMOJI`). Inline `onclick=` handlers must keep resolving.
- **No build tools.** Vanilla browser-native APIs only.
- **Single-purpose, bisectable commits** (one per phase below). Each
  independently smoke-testable. No automated tests — discipline is the net.
- **Service worker lockstep**: every file added → `SHELL` += that path,
  `CACHE` bumped (`divelog-vN` → `v(N+1)`), or offline silently breaks.
- **Leaflet via unpkg CDN** (already loaded in `index.html` for the
  existing map panel — confirm and reuse; do not double-load).
- **Reuse `SP_PHOTO_MAP` and `SP_IUCN_MAP`** from `js/species.js` for
  photo URLs and IUCN status by scientificName. Don't rebuild lookup maps.
- **Reuse `GROUP_EMOJI`** for category labels (do not hardcode emoji).
- **Colour system v2** (`CLAUDE colour UI.md`): reuse only.
  - IUCN tier colours are already defined in the mockup CSS — port them
    *as-is* into the album stylesheet. Do not invent new IUCN colour
    semantics; the rarity ramp (CR → EN → VU → NT → LC → DD) is locked.
  - ▶ video-ref glyph: `var(--accent)` (interactive role — even though
    passive in v3.0, the colour reads as "this will do something"; matches
    the dive card).
- **Type scale**: `--xs` 12px, `--sm` 14px, `--base` 16px — no off-scale
  font-sizes (per the locked rule in `CLAUDE.md`). Hero name is the one
  exception (20px, mirroring the modal patterns).
- **Frontmatter unchanged.** This feature is *read-only* over existing
  dive data. No new fields, no new YAML keys, no schema migration.

## 4. Data model

**No schema changes.** The album panel is a *derived view* over the
existing in-memory `dives[]` array. Each render computes:

```js
// 4.1 Aggregate sightings by species
//   key = scientificName (canonical) — falls back to commonName if
//   scientific is empty
//
// speciesIndex: Map<sciName, {
//   commonName,
//   scientificName,
//   aphiaId,
//   group,
//   iucn,                  // from SP_IUCN_MAP, '' if unknown
//   photoUrl,              // from SP_PHOTO_MAP, '' if unknown
//   diveCount,             // number of distinct dives this species appears on
//   videoCount,            // number of sightings with a `video` field set
//   lastSeen,              // most-recent dive date (ISO yyyy-mm-dd)
//   sightings: [           // sorted by dive.date DESC
//     {
//       diveId, divenum, site, region, location,
//       gps_lat, gps_lng,  // may be null
//       date,               // ISO
//       abundance,          // 'R' | 'O' | 'C' (or '' for legacy)
//       video,              // optional — filename
//       time                // optional — 'mm:ss'
//     },
//     ...
//   ]
// }>
```

**Group order**: alphabetical by group label (not BROWSE_GROUPS order).
The mockup confirms this: Cephalopod, Eel, Fish, Mollusc, Ray, Reptile,
Shark when those are the groups present. Only render a group section if
≥1 species in that group has been logged.

**Within-group sort**: IUCN rarity descending (CR → EN → VU → NT → LC →
DD → unknown), with **alphabetical sub-sort by common name** inside each
tier.

**Counting rule**: `diveCount` is *distinct dives*, not total sightings.
A species seen twice on the same dive counts once. (Matches the existing
Stats panel's "dives where a species was seen" rule — see CLAUDE.md →
*Species sighting stats*.)

## 5. UI surfaces (visual spec → see mockup)

Reference: `mockups/mockup-species-album.html`

### A. New **Species** panel (`#panel-species`)

- Becomes the 4th main panel. Nav entry order (sidebar + mobile tab bar):
  Log, History, Species, Stats, Data. The Species tab pushes Stats and
  Data right by one position.
- Icon for nav: 🐠 (or whatever the existing nav convention uses for icons
  — match Stats / History style).
- Panel head: `<h1>Species</h1>` + sub line `N species recorded across M
  dives` (use a mono small-caps font as in the mockup).
- Search bar (sort dropdown explicitly **not** included).
- **Sticky category nav** (`.catnav` in the mockup) — horizontal pill
  strip, scrollable on mobile, anchor links jumping to each group section.
- One `.gsec` per group present in the user's logged data, ordered
  alphabetically by group label.
- Each `.gsec` renders a horizontal `.strip` with thumbnails. Use
  `scroll-snap-type: x mandatory` (mobile = swipe, desktop = arrows). The
  arrow buttons (‹ ›) on the header should scroll the strip by one
  card-width.
- Thumbnail = `.thumb` with `.photo` (iNat URL or emoji placeholder
  fallback) + `.meta` block of `.nm` (common name) + `.row` (IUCN badge
  + dive count).
- Empty state (no logged species): a single centered panel with the
  locked copy `"No species recorded yet — log a dive or sync your data."`
  No catnav, no group sections, no search bar (or show search bar
  disabled — designer's call, lean toward hiding for minimalism).
- **Search behaviour**: filters the thumbnails *inline* — groups with
  zero matches hide; matching thumbs stay in their groups, retaining
  rarity sort. No flat-list fallback. Search is local string-contains
  (case-insensitive) on commonName + scientificName.

### B. Species profile modal (`#species-profile-modal`)

- Modal frame: same overlay / animation pattern as existing `#edit-modal`
  and `#footage-modal`. Tap backdrop or ✕ to close.
- Header: simplified — just an ✕ in the top-right (the species name is
  in the hero immediately below; no redundant title bar).
- **Hero** block:
  - Left: 140×140 photo (iNat `medium.jpeg` variant if available — derive
    from `SP_PHOTO_MAP` by swapping `square` → `medium` in the URL where
    pattern matches `…/photos/<id>/square.<ext>`; fall back to the
    `square` URL or the group emoji placeholder).
  - Right: common name (20px / 700), scientific name (italic, sm,
    muted), badges row (IUCN pill + group tag), stats line: `N dives  ·
    M video references  ·  last seen <Day DD Mon YYYY>`.
- **"Where you've seen it"** section: Leaflet map. One marker per
  *distinct site* the species was logged at, **only for sightings with
  `gps_lat`/`gps_lng` set**. If no sightings have GPS, hide this section
  entirely (don't render an empty map). Markers bind a tooltip showing
  `#divenum Site · Day DD Mon YYYY`. `fitBounds` to the marker set with
  reasonable padding. Tile provider: same as the existing map panel
  (OpenStreetMap default).
- **"Sightings"** section (`.sightings`): one `.dive-block` per logged
  dive, sorted most-recent first. Row = `#divenum`, `site · region,
  country`, `Day DD Mon YYYY`, abundance pill (R/O/C). If the sighting
  has a `video` field set, render a **passive** `.video-ref` row
  beneath: `▶ <filename> @ <time>`. Hover the row → no playback action
  in v3.0; the row is informational. Cursor stays default — don't fake
  affordance.

### C. Entry points

- v3.0: **only** the nav tab opens this panel. Do not add deep links from
  dive cards, History timeline rows, or anywhere else. (Future work may
  add a "see this species" affordance on individual sighting rows —
  scope it later.)

## 6. Implementation phases (one commit per phase)

Each phase = a single-purpose, bisectable commit. Smoke-test before the
next. Follow the established recipe (see `v2.0-BRIEF-video-footage.md`
§8 — it applies verbatim).

### Phase 1 — Species index (data layer only, no UI)
- New file `js/album.js` (classic script, loaded before main inline
  `<script>`).
- Implement `buildSpeciesIndex(dives)` → `Map<sciName, SpeciesEntry>` per
  §4.
- Implement helpers: `_iucnRank(status)` (CR=5, EN=4, VU=3, NT=2, LC=1,
  DD=0, ''=−1), `_groupSpeciesByGroup(index)`, `_sortGroupContents(arr)`.
- Expose nothing to the UI yet — but make these functions globally
  callable so they can be unit-tested from the browser console.
- `sw.js`: `SHELL` += `/js/album.js`, `CACHE` bump.
- Smoke: open DevTools → `buildSpeciesIndex(dives)` returns a Map with
  correct counts; spot-check 2 species. Verify alphabetical group order
  and IUCN sort with `_groupSpeciesByGroup(buildSpeciesIndex(dives))`.
- **Commit:** `3.0a - Species index: build derived view over dives`

### Phase 2 — Species panel shell + nav entry
- Add `#panel-species` to `index.html` (empty container — just panel
  head + search bar + catnav placeholder).
- Add nav entry (sidebar + mobile tab bar) for Species, positioned
  between History and Stats.
- Wire `show('species')` through the existing `show(name, btn)` patched
  function. Do **not** add another patch to `show()` — extend the
  existing unified patch if any panel-switch behaviour is needed (see
  CLAUDE.md → *Panels / navigation*).
- Render the empty state if `dives.flatMap(d => d.marine).length === 0`.
- Otherwise render: `Species` heading + sub-count line + search input +
  empty catnav (Phase 3 fills it).
- Smoke: nav to Species → panel switches, shell renders correctly, empty
  state shows when no species logged.
- **Commit:** `3.0b - Species panel: shell + nav entry`

### Phase 3 — Group sections + thumbnails
- Render `.catnav` with one `.cat-pill` per group present in the index
  (alphabetical, with `GROUP_EMOJI[group]`).
- Render `.gsec` per group with `.gsec-h` header (emoji + label + count +
  arrow buttons) and `.strip` body.
- Render `.thumb` per species: photo from `SP_PHOTO_MAP` (or emoji
  placeholder), `.nm` common name, `.row` IUCN badge + `N dives` sub.
- Arrow buttons scroll the strip by one card width (`scrollBy` with
  smooth behaviour).
- Anchor links in catnav scroll to the matching `#cat-<group>` section
  (use `scrollIntoView` with `scroll-margin-top` set on `.gsec` to clear
  the sticky catnav).
- Thumbs are clickable but click handler is a stub (Phase 4 wires the
  modal).
- Smoke: panel shows all logged-species groups; alphabetical group
  order; rarity sort within each strip; clicking a catnav pill jumps to
  the right section; arrows scroll the strip.
- **Commit:** `3.0c - Species panel: group sections + thumbnails`

### Phase 4 — Species profile modal: open, hero, sightings list
- Add `#species-profile-modal` HTML to `index.html` (analog of
  `#edit-modal` / `#footage-modal`).
- New functions in `js/album.js`: `openSpeciesProfile(sciName)`,
  `closeSpeciesProfile()`.
- Wire thumbnail click → `openSpeciesProfile(t.scientificName)`.
- Render hero (photo / name / sci / IUCN / group / stats line).
- Render `.sightings` block with `.dive-block` rows. If a sighting has
  `video` + `time`, render the **passive** `.video-ref` row beneath
  (matches the visual in the mockup — no click handler, cursor default).
- Backdrop click + ✕ close.
- Smoke: tap any thumbnail → modal opens with the right species → hero
  + sightings render → close works.
- **Commit:** `3.0d - Species profile modal: open, hero, sightings`

### Phase 5 — "Where you've seen it" map
- Confirm Leaflet is already loaded for the existing map panel; if not,
  add to `index.html` head (CSS + JS via unpkg).
- In `openSpeciesProfile()`: gather sightings with `gps_lat && gps_lng`,
  deduped by `lat,lng` (1 marker per distinct site).
- If ≥1 marker: render the map section + `fitBounds`. Marker tooltip:
  `#<divenum> <site> · <Day DD Mon YYYY>`.
- If 0 markers: hide the entire `.sec` containing the map (do not show
  an empty box).
- **Modal teardown**: `L.map.remove()` on close, or guard against
  re-init by `_speciesMap?.remove()` before each open. Leaflet leaks
  hard if you don't.
- Smoke: open a species seen at multiple sites with GPS → map shows the
  right markers, fitBounds works → close + reopen 5× → no console errors,
  no memory creep.
- **Commit:** `3.0e - Species profile modal: map of sites`

### Phase 6 — Search + final polish + version stamp
- Wire the search input → live filter on thumbnails (case-insensitive
  contains on commonName + scientificName).
- Hide `.gsec` blocks where every thumb is filtered out. Hide
  `.cat-pill` entries whose group section is hidden.
- Empty search-result state: small inline `"No matches."` line below the
  bar; show again as soon as the query clears.
- Verify all empty states (no species, no GPS, no matches, single-group,
  single-species).
- Verify mobile responsive layout (≤600px): catnav scrolls horizontally,
  thumbs stay 140-152px wide, hero stacks centered.
- Inline-handler sanity: grep for `onclick=` references; confirm no
  collisions with existing handlers.
- Append the v3.0 feature record to `DECISIONS.md` (new section: *Species
  Album — Layer 1*).
- Stamp version → 3.0 (confirm with user before stamping).
- **Commit:** `3.0 - Species Album L1: search + polish + version stamp`

## 7. Edge cases & details Sonnet must get right

- **Scientific name as key**: aggregate by `scientificName`. If a
  sighting has no `scientificName` (legacy free-text entries), fall back
  to `commonName` as the key — but DO display a small unvalidated
  indicator (e.g. dim italic `?` next to the badges) on the modal so the
  user knows this entry hasn't been WoRMS-matched. **Don't** try to
  resolve it at album-render time — that's a separate feature.
- **Missing photos**: if `SP_PHOTO_MAP[sciName]` is empty, fall back to
  the group emoji (`GROUP_EMOJI[group]`) as a `.ph` placeholder. Match
  the existing browse-mode placeholder style.
- **Missing IUCN status**: if `SP_IUCN_MAP[sciName]` is empty, omit the
  IUCN pill from both thumbnail and hero. Sort treats unknown as the
  *lowest* rarity (after DD).
- **Dive count > 1 at same site**: the map still shows 1 marker per
  distinct site. The sightings list shows all dive rows.
- **Sightings list date format**: `Day DD Mon YYYY` (e.g. `Wed 13 May
  2026`) using the same formatter as the History timeline trip headers.
  Don't invent a new format.
- **`last seen`**: max of `dive.date` across the species' sightings —
  formatted the same way.
- **Sub-fold render performance**: 1,000+ thumbs is unrealistic but be
  defensive — set `loading="lazy"` on every `<img>` and `decoding="async"`.
  Don't pre-create off-screen DOM beyond the visible strips (browser will
  handle horizontal-scroll lazy loading natively).
- **Reusing the dive-form species search engine**: not needed in v3.0 —
  the album search is a flat string-filter over the index, not a species
  picker. **Do not** touch `_browseCtx` or the shared browse state.
- **Modal A11y**: backdrop click closes; `Esc` closes; focus trap is a
  nice-to-have but not required for v3.0 (matches existing modals).
- **No keyboard arrow nav between thumbs in v3.0** — the strip is mouse/
  touch / arrow-button only. Defer keyboard nav to a polish pass.

## 8. The recipe (mirror the migration discipline)

Same as `v2.0-BRIEF-video-footage.md` §8. Verbatim:

For each phase:

1. **Clean baseline** — `git status` confirms `index.html` (and any other
   touched files) committed before starting.
2. **Implement** the phase's narrow scope.
3. **Verify**:
   - `jsc js/album.js` (if touched) — no `SyntaxError`.
   - Extract + parse the inline `<script>`:
     `python3 -c "import re;h=open('index.html').read();open('/tmp/dc.js','w').write(chr(10).join(re.findall(r'<script>(.*?)</script>',h,re.S)))"`
     then `/System/Library/Frameworks/JavaScriptCore.framework/Versions/A/Helpers/jsc /tmp/dc.js 2>&1 | grep -i syntaxerror`
   - Targeted greps (no stale refs, expected refs present).
4. **`sw.js` lockstep** when adding new files: `SHELL` += path, `CACHE`
   `v(N)` → `v(N+1)`.
5. **Docs**:
   - `CHANGELOG.md` `## [Unreleased]` bullet (write *as part of the
     phase*, not retroactively).
   - `DECISIONS.md` progress line under a new "Species Album" decision
     section.
   - `README.md` repo-map row if a new file was added.
6. **Hand off to user for smoke test** with a checklist tailored to that
   phase.
7. **On explicit "ready to commit"**: stamp `[Unreleased]` →
   `## [3.0x] – <date> — <phase summary>` + open a fresh empty
   `[Unreleased]`. Tell the user the exact files to stage in GitHub
   Desktop and which to leave (single-purpose commit).

## 9. After v3.0 ships — what comes next (do not implement)

For context only:

- **v3.1 (Layer 2 — personal photos)**: deferred pending an
  architectural decision. Two paths under consideration:
  - **File System Access API** (same path as v2.1 video playback —
    desktop Mac primary). User grants access to a photo folder; handle
    persisted in IndexedDB; album thumbnails resolve to local file URLs.
    No backend.
  - **Small backend** (Cloudflare Worker OAuth proxy) for cloud APIs
    (Google Photos / iCloud Photos). Adds operational surface but
    enables cross-device.
  - Decision is **deferred** — user has flagged it as "revisit when L2
    work begins."
- **Video playback in album**: when v2.1 ships in-app playback, the ▶
  row in the species profile modal becomes clickable (same handler as
  the Footage section on the dive card). Build once playback exists on
  both surfaces simultaneously.
- **Pokédex extension**: render the full 1,010-species set in a separate
  view (greyed-out for undiscovered, full-colour for discovered), with
  gamification hooks (rarity tier counts, milestones). Out of scope for
  v3.0; revisit as a separate roadmap item.
- **Deep-link entry**: a "see this species" affordance on individual
  sighting rows in the dive card / History timeline. Scope when there's
  a real workflow need.
- **Tap-marker-to-open-dive** on the map: open the dive's expanded card
  from a marker popup. Defer until mobile interaction is verified.
